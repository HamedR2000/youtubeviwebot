# پایپ‌لاین ری‌اکشن ویدیو (اینستاگرام → یوتیوب Shorts)

دانلود کلیپ منبع، ترکیبش با یه پنل ری‌اکشن (کپشن + آواتار) در فرمت عمودی Shorts، و آپلود به یوتیوب. فعلاً بدون صدا/لب‌سینک کار می‌کنه (چک‌لیست پایین‌تر) — آواتار فقط یه عکس ثابته با یه نوسان ملایم، نه ویدیوی لب‌سینک‌شده‌ی HeyGen/D-ID.

## جریان کار (نیمه‌خودکار، طبق درخواست)

```bash
cd reaction_bot
pip install -r requirements.txt   # نیاز به ffmpeg هم هست: apt install ffmpeg

# قدم ۱: کلیپ رو دانلود کن و اسکریپت رو پیش‌نمایش کن (بدون --approve چیزی ساخته نمی‌شه)
python main.py --source "https://www.instagram.com/reel/XXXXX/" \
  --script "متن واکنش من به این ویدیو..."

# قدم ۲: بعد از این‌که از متن مطمئن شدی، همون دستور رو با --approve بزن تا ویدیوی نهایی ساخته بشه
python main.py --source "https://www.instagram.com/reel/XXXXX/" \
  --script "متن واکنش من به این ویدیو..." --approve

# قدم ۳: بعد از دیدن فایل خروجی (workdir/outputs/) اگه راضی بودی، آپلود کن
python main.py --source "https://www.instagram.com/reel/XXXXX/" \
  --script "متن واکنش من به این ویدیو..." --approve --upload --privacy unlisted
```

- `--source` هم لینک اینستاگرام قبول می‌کنه (با `yt-dlp` دانلود می‌شه — فقط برای پست‌های عمومی جواب می‌ده) هم مسیر یه فایل ویدیویی محلی که خودت از قبل ذخیره کردی.
- به‌جای `--script` می‌تونی `--script-file script.txt` بدی — برای متن‌های بلندتر راحت‌تره.
- بدون `--approve` فقط دانلود و پیش‌نمایش متن انجام می‌شه و متوقف می‌شه — دقیقاً همون قدم تأیید/ویرایش اسکریپت قبل از تولید نهایی که خواسته بودی.
- بدون `--upload` فایل نهایی توی `workdir/outputs/` می‌مونه تا خودت قبل از پابلیک شدن نگاهش کنی؛ آپلود کاری نیست که خودکار/بی‌سروصدا انجام بشه.
- پیش‌فرض `--privacy` روی **`private`**ه (نه public) — عمداً همینه، تا خودت از یوتیوب استودیو تصمیم نهایی انتشار رو بگیری. برای انتشار مستقیم باید صریحاً `--privacy public` یا `--privacy unlisted` بدی.
- `--dry-run` (کنار `--upload`) فقط چیزی که قراره به یوتیوب فرستاده بشه رو چاپ می‌کنه، هیچی واقعاً آپلود نمی‌شه — برای تست.

## چیدمان ویدیوی خروجی

بوم عمودی ۱۰۸۰×۱۹۲۰ (۹:۱۶، مناسب Shorts):
- **بالای صفحه (~۶۰٪ ارتفاع، قابل تنظیم با `REACTION_SOURCE_HEIGHT_RATIO`):** کلیپ منبع، کراپ‌شده تا این ناحیه رو پر کنه — **تمام صفحه نیست**، طبق نکته‌ی ریسک کپی‌رایت.
- **پایین صفحه:** پنل ری‌اکشن با بج «ری‌اکشن»، عکس آواتار (اگه بدی) سمت چپ، و متن اسکریپتت (فارسی، راست‌به‌چپ) سمت راست، طوری که روی هم نیفتن.
- صدای کلیپ منبع نگه داشته می‌شه؛ اگه `--voice path/to/audio.mp3` بدی (ضبط خودت یا خروجی TTS)، اون رو روی صدا میکس می‌کنه و صدای منبع رو کم می‌کنه (duck) — فعلاً چون تصمیم گرفتی بدون صدا کار کنیم، این پارامتر اختیاریه و به آواتار سینک نمی‌شه.

## آواتار ری‌اکشن

پایپ‌لاین خودش کاراکتر تولید نمی‌کنه — فقط یه عکس آماده رو کنار متن می‌ذاره و بهش یه نوسان ملایم بالا/پایین می‌ده (چون فعلاً صدا/لب‌سینک نداریم). کاراکتر فعلی: یه پسر خوش‌خنده، مشخصاً روی ویلچر نشسته، ساخته‌شده با Bing Image Creator (سبک عکس واقعی، نه کارتون) و ذخیره‌شده توی `reaction_bot/assets/avatar.png`.

عکسی که خودت با AI ساختی و آپلود کردی پس‌زمینه‌ی معمولی (اتاق نشیمن) داشت؛ من با `rembg` (ابزار حذف پس‌زمینه‌ی محلی/رایگان) پس‌زمینه رو حذف کردم و تصویر رو تنگ دور خودِ پسر/ویلچر کراپ کردم تا روی پنل تیره‌ی ری‌اکشن تمیز بشینه.

**اگه خواستی یه عکس دیگه/پوز دیگه بسازی:** همون ابزارها (Bing Image Creator، Leonardo.Ai، Midjourney) با همون پرامپت قبلی جواب می‌دن. فایل جدید رو جایگزین `assets/avatar.png` کن (پس‌زمینه‌ش هرچی بود مهم نیست، دوباره پردازشش می‌کنم) — یا موقتاً با `--avatar path/to/file.png` تستش کن بدون این‌که فایل پیش‌فرض رو عوض کنی.

**نکته‌ی چیدمان:** عرض نمایش آواتار به‌صورت خودکار محدود می‌شه (حداکثر ~۴۲٪ عرض بوم) تا جای کافی برای متن کپشن بمونه، حتی اگه عکس منبع پهن باشه (مثلاً ویلچر کنارش باشه).

## راه‌اندازی یوتیوب (OAuth)

آپلود از طریق YouTube Data API v3 با اکانت خودته، نه پسورد:

1. برو به [Google Cloud Console](https://console.cloud.google.com/) و یه پروژه بساز (یا از پروژه‌ی موجود استفاده کن).
2. از `APIs & Services → Library`، **YouTube Data API v3** رو فعال کن.
3. از `APIs & Services → OAuth consent screen`، نوع رو `External` بذار (کافیه خودت رو به‌عنوان test user اضافه کنی، نیازی به تأیید گوگل برای استفاده‌ی شخصی نیست).
4. از `APIs & Services → Credentials → Create Credentials → OAuth client ID`، نوع اپ رو **Desktop app** انتخاب کن و بسازش.
5. JSON دانلودش کن و به اسم `reaction_bot/client_secret.json` ذخیره‌اش کن (یا مسیرش رو با `YOUTUBE_CLIENT_SECRETS_FILE` در `.env` بده).
6. اولین بار که `--upload` بزنی، یه لینک گوگل باز می‌شه (یا لوکال سرور می‌گیره) تا با اکانت یوتیوبت لاگین/تأیید کنی؛ بعدش توکن توی `reaction_bot/token.json` ذخیره می‌شه و دفعات بعد نیازی به لاگین دوباره نیست (`client_secret.json` و `token.json` هر دو توی `.gitignore` هستن، هیچ‌وقت کامیت نمی‌شن).

⚠️ **محدودیت quota:** پروژه‌ی جدید گوگل روزانه ۱۰,۰۰۰ واحد quota پیش‌فرض داره و هر آپلود ویدیو ~۱۶۰۰ واحد مصرف می‌کنه — یعنی حدود **۶ آپلود در روز**. برای بیشتر باید از همون Cloud Console درخواست افزایش quota بدی (فرم "Quotas" → YouTube Data API؛ چند روز طول می‌کشه تا گوگل جواب بده).

## نکات حقوقی/ریسک (رعایت‌شده در این پیاده‌سازی)

- کلیپ منبع همیشه فقط بخشی از فریم رو می‌گیره (پیش‌فرض ۶۰٪ ارتفاع)، نه تمام صفحه.
- پنل ری‌اکشن جای واقعی و قابل‌توجه روی صفحه داره (نه یه لوگوی کوچیک تو گوشه) تا واکنش/تفسیر بخش محسوسی از ویدیو باشه، نه صرفاً بازپخش خام.
- توصیه‌ی پروژه: توی توضیحات ویدیوی یوتیوب همیشه به صاحب کلیپ اصلی کردیت بده (نام/آیدی اینستاگرام) — فیلد `--description` برای همینه.
- دانلود از اینستاگرام (`yt-dlp`) فقط برای محتوای عمومی جواب می‌ده و طبق ToS اینستاگرام باید با احتیاط استفاده بشه؛ این ابزار مسئولیت انتخاب و اجازه‌گیری از منبع رو خودکار نمی‌کنه.
